# Editing game content

Every record lives in its own JSON file under `content/`. VS Code provides completion and field validation using the generated schemas in `content/schemas/` and `.vscode/settings.json`.

The sample species, moves, abilities and items demonstrate the data model. Their values are example game balance, not a canonical Pokémon database. Combat, abilities, learning moves and usable items are not implemented. Only the `awakening-woods` dungeon's map, spawn and collectible positions currently drive gameplay. Effect IDs describe future behavior; they do not execute code.

## Add or change a record

1. Copy a file in the relevant category: `species`, `moves`, `abilities`, `items` or `dungeons`.
2. Give it a unique, stable lowercase hyphenated `id`; the filename must be `<id>.json`.
3. Edit its fields. Species reference abilities through `abilityIds` and moves through `learnset[].moveId`. Dungeons reference items through `collectibles[].itemId`.
4. Run `npm run content:generate` to validate every file and regenerate the import manifest and JSON schemas.
5. Run `npm run check` and `npm test` before sharing changes. Commit the JSON files and generated files together.

Keep existing IDs stable: saved data and other records may reference them. The current playable dungeon must retain the ID `awakening-woods`. Preserve its existing collectible order when changing a map; version 1 saves store collectible indexes.

## Dungeon rules

Map rows must have equal widths. `#` is a wall, `~` is water and `.` is walkable floor. Coordinates start at zero in the top left. The spawn and every collectible must occupy floor; every collectible must be reachable from the spawn, and positions cannot repeat. `tileSize` is the source tile size used by rendering.

## Source boundaries

- `src/content/schemas.ts` defines strict record shapes and exported TypeScript types.
- `src/content/validate.ts` checks IDs, references, map geometry and reachability.
- `src/content/catalog.ts` validates and exports the catalog plus the playable field.
- `src/content/manifest.ts` is generated by `scripts/content.mts`; do not edit it manually.
- `scripts/content.mts --check` verifies the source files and detects stale generated outputs without rewriting them.

The content layer imports no gameplay, UI, browser storage or rendering modules. Add a schema field before adding it to JSON; unknown fields are rejected. Implement new effect behavior explicitly in the domain layer before describing it as functional.
